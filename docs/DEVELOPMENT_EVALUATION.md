Qwen3-VL-4B-Instruct, snapshot `ebb281ec70b05090aa6165b016eac8ec08e71b17`, RTX A5000 24 ГБ. Другой процесс занимает часть GPU; его не останавливали. Обработка выполняется локальной моделью на уже арендованном командой Pod, без внешних AI API. Новые платные ресурсы не создавались. Веса не обучались.

Это проверка разработки, **не независимая оценка**: общий профиль подсказок получен из положительных описаний того же открытого обучающего набора. Нет подтверждённых групп связанных сцен и отдельных категорий/интервалов событий для всех видео. Бинарные эталоны и точечные таймкоды используются только после анализа для подсчёта метрик; имена файлов, эталонные метки и таймкоды не передаются в промпт распознавания.

## Видеовход и общий профиль

Режим `video/narrative`, около 2 кадров/с с покрытием всей записи, затем обязательная повторная проверка пустого обзора. Общий профиль содержит семь шаблонов действий, без имён файлов или ответов для конкретных видео.

| Проверка | Положительных | Отрицательных | TP | FN | TN | FP | Сбоев |
|---|---:|---:|---:|---:|---:|---:|---:|
| Ранее пропущенный ролик 25,6 с | 1 | 0 | 0 | 1 | 0 | 0 | 0 |
| Три самых коротких ролика каждого класса | 3 | 3 | 0 | 3 | 3 | 0 | 0 |

Время непосредственного анализа шести коротких роликов: 24,60–43,09 с. Это не полное время HTTP-запроса с очередью. Отсутствие ложных срабатываний при нулевом числе найденных событий не подтверждает полезность детектора. Эта конфигурация не принята для рабочего сервиса.

## Первые варианты проверки каждой категории

Первый вариант checklist с дробными таймкодами: 7 видео (4 положительных, 3 отрицательных), TP=0, FN=1, TN=2, FP=0, failed=4. В прежнем пропуске обзор предложил одного кандидата, но окончательный этап вернул пустой ответ без объяснения. Сбои не включены в отрицательные вердикты.

Следующий вариант с индексами кадров потребовал дополнительного ограничения формата: на прежнем пропуске генерация достигла 4096 токенов и не закрыла JSON; на другом положительном примере список доказательств превысил допустимые три элемента. Это ошибки вывода модели, а не подтверждение отсутствия нарушения.

В `category-screening-v6` добавлено локальное ограничение токенов по JSON-схеме через [LM Format Enforcer](https://github.com/noamgat/lm-format-enforcer). Ограничиваются структура, длина строк и массивов, но не выбор положительного или отрицательного ответа. Проверка фактических условий категории и границ кадров остаётся обязательной после генерации. Ограничение формата само по себе не улучшает доказанность или полноту распознавания.

Первый прогон v6 завершился ошибкой на всех семи видео: библиотека допускала первый русский символ, затем преждевременно завершала строку. Причина воспроизведена локальным тестом: кэш алфавита minLength создавался до добавления Unicode-алфавита токенизатора. В v7 алфавит передаётся при создании парсера; тест с русской строкой и minLength проходит. До реальной проверки это исправление нельзя считать подтверждением качества детектора.

После неуспешных экспериментов восстановлен режим images/narrative без профиля подсказок. Проверка через настоящий API: синтетическое видео done/no_violation за 21,161 с; прежний положительный ролик — done/no_violation за 50,42 с, то есть пропуск сохранился. На синтетическом материале описание модели содержит указание цвета/одноцветного изображения; это подтверждает работу визуального входа, но не способность распознавать нарушения. Неавторизованный запрос к реальному заданию отклонён с 401.

## Исправленный ограничитель v7

Русский JSON проходит валидацию, но прежний положительный ролик 25,6 с снова получил no_violation: 0 кандидатов, 0 событий, 281,48 с непосредственного анализа. Два прохода сформировали 2616 и 2134 токена. Из-за отсутствия улучшения и близости к deadline дальнейший сравнительный прогон остановлен; его неполные задания не объявлены отрицательными и не включены в итоговые метрики. V7 не принята для рабочего сервиса. Все 42 исходных видео перенесены, но полная оценка 42 видео не проведена.

Для следующего этапа подготовлен отдельный частный файл сверки 42 записей: исходное описание, исходный точечный таймкод и неподтверждённое предложение категории от локальной модели. Подтверждённые категории, интервалы, scene_id и split оставлены пустыми. Это материал для ручной проверки, не готовые обучающие метки; веса не обучались.

## Воспроизведение внутри разрешённого контура

Остановить только свой backend при отсутствии активных заданий: эксперимент загружает собственную копию модели. Не запускать несколько таких процессов одновременно на той же GPU. Полные результаты, кадры, текст разметки и сгенерированный профиль держать в частной директории, вне Git; вывод скриптов ограничен числовыми метриками, категориями и техническими кодами ошибок.

```bash
cd /opt/forte-cash-review
.venv/bin/python scripts/prepare_calibration.py \
  --records /private/labels/team-records.jsonl --output-dir /private/guidance
.venv/bin/python scripts/evaluate_private_dataset.py \
  --dataset-dir /private/videos --audit /private/labels/dataset-audit.json \
  --profile /private/guidance/profile.json --input-mode video \
  --discovery-style checklist --limit-per-label 3 --output-dir /private/experiment
```

После эксперимента перезапустить backend и проверить `/health/ready`. Результаты прямого вызова pipeline не являются проверкой очереди и HTTP API. `scripts/benchmark.py` выполняет отдельную проверку через настоящий API. Предложения `scripts/diagnose_private_annotations.py` являются гипотезами модели, не подтверждённой разметкой; они не изменяют эталоны, таксономию или результаты распознавания.
