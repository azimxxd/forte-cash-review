> Устаревшее: описание первого пода тиммейта. Текущий сервис и запуск — в [README](../README.md).

Сервер команды: SSH `root@63.141.33.150`, порт `22189`. GPU RTX A5000 24 ГБ. Backend установлен отдельно в `/opt/forte-cash-review`. Python 3.12 использует отдельный venv с доступом к системным Torch 2.8.0+cu128 и torchvision 0.23.0+cu128; Transformers 4.57.1 установлен только в этом venv. Системное окружение тиммейта не менялось.

Веса загружены тиммейтом. Исходный кэш:

```text
/workspace/.cache/huggingface/hub/models--Qwen--Qwen3-VL-4B-Instruct/snapshots/ebb281ec70b05090aa6165b016eac8ec08e71b17
```

Обе части safetensors присутствуют: 4 967 229 296 и 3 908 490 048 байт. Исходный кэш находится на сетевом NFS-диске RunPod; чтение каталогов задерживалось на десятки секунд и минуты. Для текущего запуска создана отдельная копия в `/opt/forte-models/Qwen3-VL-4B-Instruct`: 12 файлов, 8 887 284 080 байт. SHA256 каждого скопированного файла сравнен с потоком чтения исходного файла; манифест находится внутри копии. `CASH_MODEL_PATH` указывает на эту локальную копию. Повторное скачивание весов не запускалось. Копия на `/opt` может исчезнуть при пересоздании контейнера; исходный NFS-кэш не изменён.

После прямого разрешения пользователя 17 октября 2026 на сервер переданы 42 обучающих видео (292 870 994 байта) и подробная таблица команды. SHA256 всех видео проверены. Они находятся в закрытой `/opt/forte-private-data`, отдельно от кода; оригиналы не меняются. Кадры и подробные ответы остаются на этом хосте, вне Git. Перед первым запуском сервиса на GPU уже было занято около 8,7 ГБ другим процессом; его не останавливали.

## Доступ с Mac

```bash
ssh -N -i ~/.ssh/id_ed25519_runpod -p 22189 \
  -o ExitOnForwardFailure=yes -o ServerAliveInterval=20 -o ServerAliveCountMax=3 \
  -L 127.0.0.1:8001:127.0.0.1:8000 root@63.141.33.150
```

Откройте http://127.0.0.1:8001. Логин `reviewer`, пароль совпадает с `CASH_UI_PASSWORD` в локальном `.env`. Конфигурация текущего сервера с теми же секретами сохранена локально в игнорируемом `.env.runpod` (0600) и удалённо в `/opt/forte-cash-review/.env` (0600). API-ключ не передаётся в браузер. Сервер слушает только loopback; публичный API для жюри ещё не опубликован.

## Процесс сервиса

Сервис работает в tmux-сессии `forte-cash-review`. Веса загружаются один раз в отдельном worker. Параметры первого запуска: `CASH_MAX_VISUAL_TOKENS=12000`, `CASH_MAX_INPUT_TOKENS=24000`, `OMP_NUM_THREADS=4`. Эти параметры выбраны при занятой части VRAM. Первые реальные проверки выявили пропуски; качество детектора не подтверждено. Для экспериментов backend временно останавливается только при отсутствии активных заданий, чтобы не держать две копии модели на GPU.

После входа на сервер:

```bash
cd /opt/forte-cash-review
curl http://127.0.0.1:8000/health/ready
tail -n 30 service.log
```

Запуск при отсутствии сессии:

```bash
tmux new-session -d -s forte-cash-review -c /opt/forte-cash-review \
  'exec env OMP_NUM_THREADS=4 TOKENIZERS_PARALLELISM=false .venv/bin/uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 1 --no-access-log > service.log 2>&1'
```

Для остановки только нашего сервиса: `tmux send-keys -t forte-cash-review C-c`. Не останавливайте чужие Jupyter kernels или GPU-процессы. Остановка backend не останавливает аренду Pod и не прекращает оплату RunPod.

Код и SQLite находятся в файловой системе контейнера `/opt`; они могут исчезнуть при пересоздании Pod. Локальный проект на Mac — источник восстановления. NFS-кэш весов находится отдельно в `/workspace`. Не рассчитывайте на автоматический перезапуск сервиса после пересоздания Pod.

## Проверка без датасета

После readiness=200, из локального проекта:

```bash
.venv/bin/python scripts/smoke_gpu.py --url http://127.0.0.1:8001
```

Скрипт генерирует трёхсекундный MOV с одноцветными кадрами и отправляет его настоящей Qwen. Он не читает исходные видео. Это проверка связи API, модели, декодирования и результата; она не оценивает качество детектора или скорость на длинных роликах. Отчёт сохраняется локально в `reports/gpu-smoke.json`.

Команда разрешила этот перенос и эксперимент. Отдельного подтверждения организаторов о допустимости такой инфраструктуры не получено; не выдавайте разрешение пользователя за ответ организаторов.

Фактический первый smoke: done/no_violation, 5.563 с по клиенту, 2.061 с на сервере. Пик выделенной памяти worker 9.6 ГБ. Это один синтетический ролик, не benchmark.
