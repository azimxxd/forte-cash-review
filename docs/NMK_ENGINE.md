# Движок nmk: двухпроходный анализ видео (Qwen3-VL-8B)

Включается настройкой `CASH_ENGINE=nmk`. Интерфейс, API, очередь заданий и тайм-ауты остаются из
`forte-cash-review`; меняется только то, как анализируется видео.

## Архитектура

1. **Область действия.** По движению в кадре находится прямоугольник, где происходят действия
   (стол, кассир, сейф, дверь); пустые края и переднего плана отрезаются. Резкие изменения освещения
   игнорируются.
2. **Проход 1 — обзор.** Модель смотрит всю обрезанную запись и фиксирует *факты с секундами*:
   приход/уход клиентов, работа с сумкой и сейфом, уход кассира. Нарушения на этом шаге не оцениваются.
3. **Проход 2 — фрагменты с движением рук.** Короткие окна, где руки работают над столом, вырезаются,
   увеличиваются и задаются узкие вопросы (пересчёт, передача денег клиенту, проверка документа и т. п.).
4. **Точечные проверки.** Каждое утверждение обзора проверяется отдельным увеличенным фрагментом в нужный
   момент: состояние стола, экрана, сейфа, ключа после ухода; дверь до/после входа; передача сумки и т. д.
   Положительный ответ перепроверяется на сдвинутом фрагменте.
5. **Правила в коде.** Нарушение выводится только при выполнении его предпосылок (например, «пересчёт без
   проверки документа» невозможен, если клиента не было). В ответе — одно наиболее обоснованное нарушение.
6. **Бюджет времени.** Каждое видео получает долю времени, при которой все задания в очереди укладываются
   в 5 минут; необязательные шаги пропускаются при нехватке времени.

Модель: **Qwen3-VL-8B-Instruct** (Apache-2.0), bf16, полностью локально. Внешние AI-сервисы не используются;
после загрузки весов интернет не нужен (`HF_HUB_OFFLINE=1`). Распознавание лиц не выполняется.

## Запуск

```bash
pip install -e .                      # зависимости сервиса
pip install "transformers>=4.57" accelerate "qwen-vl-utils[decord]" av torch
huggingface-cli download Qwen/Qwen3-VL-8B-Instruct --local-dir /root/models/Qwen3-VL-8B-Instruct
cp .env.example .env                  # задать CASH_API_KEY и CASH_UI_PASSWORD
scripts/nmk/run_service.sh            # сервис на 0.0.0.0:8000
```

Нужен GPU с ≥ 20 ГБ памяти (bf16); на меньших GPU — `CASH_NMK_PRECISION=4bit`.

## API (для жюри)

- `POST /api/v1/analyze` (поле `file`, `.mov`, заголовок `X-API-Key`) → `{"job_id": ...}`
- `GET /api/v1/jobs/{job_id}` → `processing` / `done` / `failed`; при `done` — `verdict`, `violations`
  (`type`, `timecode_sec`, `description`, `evidence_frames` — 1–3 JPEG в base64).

Клиент должен отправлять обычный `User-Agent` (curl, requests, браузер): прокси RunPod отклоняет запросы
`Python-urllib` без заголовка.

## Ограничения и известные ошибки

- Мелкие объекты (ключ в замке, отдельные купюры) при низком разрешении видео распознаются ненадёжно.
- Быстрые действия рук (возврат части денег клиенту) могут быть видны с неверным направлением передачи.
- Дверь, открытая уже в первом кадре, проверяется хуже: нет кадра «до» для сравнения.
- Нарушения, требующие невидимых данных (проводки, регистрация в системе, сверка), не оцениваются.
- При нескольких видео в очереди анализ каждого сокращается, чтобы все уложились в 5 минут.
- Результат — подсказка для проверки человеком, а не юридическое или дисциплинарное заключение.
