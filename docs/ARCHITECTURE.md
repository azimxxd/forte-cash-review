# Архитектура

Браузер → FastAPI (HTTP Basic для проверяющих) → ограниченная очередь SQLite → один постоянный CUDA-процесс → локальная Qwen3-VL → валидированный результат → защищённые API и плеер. Жюри обращается напрямую к `/api/v1/*` с отдельным `X-API-Key`. UI не получает этот ключ и не проксирует его через браузер.

SQLite хранит статус, этап, время поступления, deadline, итоговый JSON и расширенные данные. UUID определяет отдельную закрытую папку. Файлы не доступны через StaticFiles; защищённый маршрут плеера выдаёт только подготовленную MP4-копию завершённого задания. Доказательства — JPEG из оригинала с реальным PTS, без генерации, надписей или дорисовки. Изменение разрешения и JPEG-сжатие допустимы; оригинал сохраняется побайтно. Пользовательский путь не используется как путь хранения. Все проверяющие с общим паролем имеют доступ к заданиям сервиса: это один командный контур, не многопользовательская изоляция.

Один uvicorn process (`--workers 1`) обязателен; файловая блокировка не позволяет запустить ещё один сервер над той же SQLite. GPU-процесс стартует один раз, загружает модель и необязательный локальный LoRA, затем сообщает readiness. Супервизор контролирует deadline от начала HTTP-запроса, включая загрузку и очередь. При таймауте выполняющегося задания процесс завершается и модель загружается заново; во время загрузки новые файлы отклоняются. Сбой загрузки требует исправления конфигурации и перезапуска. Незавершённые задания при рестарте получают failed. Очередь не бесконечна; переполнение возвращает 429.

PyAV использует локальные библиотеки FFmpeg для метаданных и декодирования, что позволяет работать на Mac без системного ffprobe. Отдельный упакованный FFmpeg используется только для MP4-превью. При публикации нужен HTTPS reverse proxy с ограничением тела и времени загрузки: встроенный сервер не заменяет сетевой периметр. Basic-пароль и API-ключ хранить в .env, вне Git; не включать access log с чувствительными заголовками.

Обзор покрывает весь ролик. При достижении лимита кадров интервалы выборки увеличиваются. По умолчанию около 1 кадра/с, до 145 кадров; затем до 24 дополнительных кадров на кандидата. Уточнение получает и весь обзор, и плотный фрагмент; модель не вынуждена судить по независимому короткому окну. Число кандидатов ограничено; превышение бюджета завершает job ошибкой, не усечённым отрицательным вердиктом. Размер изображений адаптируется к общему лимиту визуальных токенов; фактический image grid проверяется перед генерацией. Малое разрешение может скрывать детали — параметры требуют GPU-эксперимента.

Модель выдаёт JSON; неизвестная категория, лишние поля, NaN, неправильный rule_id, обратный интервал, время вне ролика или ссылка на не показанный кадр приводят к failed. Пустой корректный ответ даёт no_violation. Это не доказывает полноту распознавания. Неопределённые и неизвестные наблюдения сохраняются в review_notes, не расширяют схему жюри выдуманными категориями. Семантическая истинность текста и соблюдение всех правил промпта не гарантируются JSON-валидацией — нужна ручная оценка и реальные замеры ложных срабатываний.

Все обращения Transformers/PEFT используют локальные директории и local_files_only. Offline и telemetry flags установлены принудительно в процессе. Для проверки полной автономности после загрузки образа/весов необходимо отдельно провести GPU-прогон в изолированной сети. В коде нет провайдеров AI API, распознавания лиц или сервиса внешней разметки. Qwen3.5 не подключён: иной model_type отвергается.

## Исправление первого отрицательного прохода

Версия `visual-discovery-v2` разделяет наблюдение и окончательную оценку. OverviewReport требует описания сцены и видимых действий; candidates содержит предложения для дальнейшей проверки. Отсутствующий норматив не удаляет видимого кандидата автоматически. На стадии verify фактические условия категории по-прежнему обязательны, юридический вывод не делается. Если первый обзор пуст, выполняется повторный обзор всей записи с другой выборкой и более крупными кадрами; только после него возможен отрицательный результат. Сбой этого этапа — failed.

При уточнении сохраняются до 24 обзорных кадров, равномерно покрывающих весь ролик, и полное текстовое описание первого обзора. До 24 подробных кадров извлекаются с увеличенным пределом 524288 пикселей; им выделяется в четыре раза больший вес бюджета, чем контекстным кадрам. Реальный image grid проверяется по числу изображений и общему лимиту токенов. Это перераспределение ограниченного бюджета, а не гарантия полноты обнаружения.

Расширенный результат сохраняет описание сцены и наблюдения модели, три примера входных кадров, число уникальных кадров, число кандидатов, факт повторной проверки и технические метрики каждого вызова (кадры, визуальные/входные/выходные токены и границы времени). Эти данные защищены UI-паролем; схема API жюри сохраняется. Во внешнюю диагностику допускаются технические числовые метрики без кадров, описаний видео и текста наблюдений. Старые результаты не пересчитываются автоматически и отмечаются в UI как предыдущая версия.
