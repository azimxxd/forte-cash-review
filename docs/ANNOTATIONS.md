# Разметка и разделение данных

Бинарная таблица не задаёт категории или интервалы. `audit_dataset.py` переносит её значения дословно и отдельно разбирает таймкод; не создаёт event-разметку. Латинская X и кириллическая Х не нормализуются. Сопоставление имён строгое.

Будущая разметка — JSONL, одна строка на событие. Поля: `video_id` (точное имя с `.mov`), `category` (одна из 7 категорий), `start_sec`, `end_sec`, `observed_action`, `rule_id` (ID категории). JSON Schema находится в `annotation.schema.json`. Файл не содержит выдуманных примеров банковских событий. Для видео без событий строк нет; его проверенную отрицательную метку храните в отдельном манифесте. Отсутствие строк само по себе не означает отрицательную разметку.

Отдельный манифест — JSON-массив объектов: `video_id`, `scene_id`, `split` (`train`, `validation`, `test`), `duration_sec`, `origin` (`open_dataset`, `team_owned`, `jury`). Укажите общую `scene_id` для связанных исходных видео, повторов одной сцены и всех её фрагментов. Группы определяет команда; автоматическое случайное разделение 42 файлов небезопасно. Один `scene_id` может иметь только один split. Данные жюри допускаются исключительно в test, никогда для обучения, настройки промпта или выбора порога.

```bash
.venv/bin/python scripts/import_annotations.py team-events.jsonl \
  --manifest team-manifest.json --output reports/validated-events.jsonl
```

Импорт проверяет таксономию, обязательные поля, пределы времени, точные имена, нормативный ID, разбиение сцен и запрет обучения на данных жюри. Пишет только новый файл, входы не меняет. Никакое обучение не запускается.

Метрики категорий в `evaluate.py`: сопоставление один-к-одному, одинаковая категория и предсказанный таймкод внутри размеченного интервала ±1 с. Для нескольких повторных прогонов benchmark каждый прогон оценивается отдельно. Текущая бинарная таблица даёт только ориентир времени; ближайшее расстояние до этой отметки не заменяет оценку всех событий. Релевантность доказательств оценивает человек, поле остаётся null до такой проверки. Для полной оценки интервалов нужен отдельный расчёт temporal IoU по расширенному результату; он пока не реализован.

## Таблица тиммейта с подробными описаниями

Для файла с колонками `наименование файла`, `таймстемп`, `нарушение / без нарушения` добавлен отдельный импорт в локальный staging. Третий столбец может содержать авторское описание вместо слова «нарушение»; бинарная метка при этом берётся из ранее проверенного audit по точному имени файла. Импорт не пытается угадывать категории по словам описания.

```bash
.venv/bin/python scripts/import_team_labels.py /absolute/path/open_labels.xlsx \
  --baseline-audit reports/dataset-audit.json \
  --output-dir reports/team-labels-review
```

Результат — `records.jsonl` и агрегированный `summary.json` в новой папке. Описания сохраняются дословно в `team_annotation`, а исходная строка и адреса ячеек — в provenance вместе с SHA256 книги. В терминал выводятся только агрегаты. Книга не изменяется. Имена с латинской X и кириллической Х остаются различными. Проверяются совпадение с метаданными, повторы строк, противоречие явной бинарной метки и пределы времени. Расхождение с прежней временной точкой выделяется для проверки.

Точечная отметка сохраняется как `reference_timecode_sec`; поля `start_sec` и `end_sec` остаются null. Отсутствующие `category`, `rule_id`, `observed_action`, `scene_id` и `split` не заполняются автоматически. `team_annotation` — утверждение автора таблицы, не автоматически подтверждённый визуальный факт или норматив. Отсутствие категории или интервала явно исключает готовность к event-обучению. Для финальной JSONL-разметки используйте формат выше после проверки и дополнения командой.

Данные staging хранятся только в игнорируемом `reports/`, с правами папки 0700 и файлов 0600. Не добавляйте их в GitHub или внешние AI-сервисы. Импорт не меняет промпт, не запускает GPU-анализ или обучение, не подставляет известные таймкоды и метки в вердикты детектора.
