# Сдача решения — Datathon 26, ForteBank

Пакет по разделу 8 ТЗ.

## 1. Адреса и доступ

| Что | Значение |
| --- | --- |
| Интерфейс | https://v3ljfap04rrur9-8000.proxy.runpod.net — без пароля |
| API | https://v3ljfap04rrur9-8000.proxy.runpod.net/api/v1 |
| API-ключ | заголовок `X-API-Key`; ключ передаётся жюри отдельным сообщением, не в репозитории |

Клиент API должен отправлять обычный `User-Agent` (curl, `requests`, браузер): прокси RunPod отклоняет голый
Python `urllib`. При переезде пода адрес меняется — актуальный указан в форме сдачи.

## 2. Запуск и использование

**Пользователь:** открыть адрес, перетащить `.mov`, нажать «Проверить». Во время анализа виден текущий этап
(обзор, фрагменты рук, проверка ухода, точечные проверки, кадры). В результате — вердикт, плеер с собственным
таймлайном (нарушение отмечено красным, клик и перетаскивание — переход), тип, секунда, краткое обоснование со
ссылкой на пункт нормы и кадры-доказательства.

**API (раздел 10 ТЗ):**

```bash
curl -X POST ‹URL›/api/v1/analyze -H "X-API-Key: ‹ключ›" -F "file=@video_017.mov"
# 202 {"job_id": "…"}
curl ‹URL›/api/v1/jobs/‹job_id› -H "X-API-Key: ‹ключ›"
# {"job_id", "status": "processing" | "done" | "failed", "verdict", "violations": [...]}
```

`violations[]`: `type` (название нарушения по-русски), `timecode_sec`, `description` (что видно и почему это
нарушение, пункт нормы), `evidence_frames` (1–3 JPEG в base64 из оригинала: весь кадр и увеличение).
Коды: 401 ключ, 404 job_id, 413 размер, 415 не `.mov`, 429 очередь, 503 модель не готова; превышение 5 минут — `failed`.

**Сервер:** `scripts/nmk/run_service.sh` на GPU-хосте (см. [README](../README.md#запуск-на-своём-gpu)).

## 3. Архитектура и модель

FastAPI (API под ключом) → очередь SQLite → постоянный GPU-процесс → двухпроходный анализ на локальной
**Qwen3-VL-8B-Instruct** (Apache-2.0, bf16, RTX A5000 24 ГБ) → правила в коде → ответ по схеме ТЗ.
Облачные AI-сервисы не используются; после загрузки весов интернет не нужен. Распознавания лиц нет.
Подробно — [NMK_ENGINE.md](NMK_ENGINE.md), кратко — [README](../README.md#как-это-работает).

## 4. Нормативные источники

Постановления Правления НБРК: № 231 (Правила кассовых операций и инкассации в БВУ), № 14 (охрана и устройство
помещений банков), № 48 (информационная безопасность банков). Тексты пунктов прочитаны в действующей редакции на
adilet.zan.kz; каждому типу сопоставлен пункт с дословной цитатой ([nmk/violation_rules.json](../nmk/violation_rules.json)).
Там, где норма прямо не называет действие, связь помечена как «выведено из текста».

## 6. Качество, ограничения и известные ошибки

Качество на 42 обучающих роликах (наша разметка, только для оценки) — [README](../README.md#качество-на-обучающих-роликах).

- Анализ только визуальный, по одной камере; проводки, сверка и регистрация операций не проверяются.
- Мелкие объекты при низком разрешении (ключ в замке, отдельные купюры) распознаются ненадёжно.
- Направление передачи денег может быть определено неверно (клиент кладёт деньги ↔ кассир возвращает).
- Дверь, открытая уже в первом кадре, проверяется хуже: нет кадра «до».
- Настройка на полноту: слабые находки сохраняются, поэтому возможны ложные тревоги на чистых роликах.
- При нескольких видео в очереди анализ каждого сокращается, чтобы все уложились в 5 минут.
- Результат — подсказка проверяющему, а не юридическое или дисциплинарное заключение.
