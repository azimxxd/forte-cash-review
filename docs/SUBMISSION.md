# Сдача решения — Datathon 26, ForteBank

Пакет по разделу 8 ТЗ. Поля в `‹…›` заполняются перед отправкой.

## 1. Адреса и доступ

| Что | Значение |
| --- | --- |
| Интерфейс | `‹https://….trycloudflare.com›` — логин `reviewer`, пароль `‹CASH_UI_PASSWORD›` |
| API | `‹https://….trycloudflare.com›/api/v1` |
| API-ключ | `‹CASH_API_KEY›`, заголовок `X-API-Key` |

Ключ и пароль передаются жюри отдельным сообщением, не в репозитории.

## 2. Запуск и использование

**Пользователь:** открыть адрес интерфейса, перетащить `.mov` (или «Выбрать видео»), нажать «Проверить». Пока идёт анализ, видно текущий этап. В результате показаны вердикт, видео с отметками на таймлайне, список нарушений (тип, таймкод, описание, кадр) и по выбранному нарушению — кадры-доказательства, что видно на видео, почему это может быть нарушением, правило и пункт НБРК.

**API (раздел 10 ТЗ):**

```bash
curl -X POST ‹URL›/api/v1/analyze -H "X-API-Key: ‹ключ›" -F "file=@video_017.mov"
# 202 {"job_id": "…"}
curl ‹URL›/api/v1/jobs/‹job_id› -H "X-API-Key: ‹ключ›"
# {"job_id", "status": "processing" | "done" | "failed", …}
```

Готовый результат строго по схеме ТЗ: `job_id`, `status`, `verdict` (`violation` / `no_violation`), `violations[]` с `type` (название типа нарушения), `timecode_sec`, `description` (что видно, почему это может быть нарушением, правило и пункт источника, ограничения вывода) и `evidence_frames` (1–3 JPEG в base64, кадры из оригинала). Коды ошибок: 401 неверный ключ, 404 неизвестный job_id, 413 файл больше лимита, 415 не `.mov`, 429 очередь заполнена, 503 модель не готова. Ошибка анализа или таймаут дают `failed`, а не `no_violation`.

**Сервер:** на GPU-хосте из папки проекта `scripts/runpod_up.sh` — поднимает сервис и HTTPS-туннель в tmux и печатает публичный адрес. Подробности — [RUNPOD.md](RUNPOD.md), локальный запуск — [README](../README.md).

## 3. Архитектура и модели

Браузер / жюри → FastAPI (UI под паролем, API под ключом) → очередь SQLite → один постоянный GPU-процесс → локальная Qwen3-VL-4B-Instruct → проверка JSON-схемы → результат. Видео декодируется локально (PyAV/FFmpeg), кадры-доказательства берутся из оригинала по реальным временным меткам. Облачные AI-сервисы не используются, после загрузки весов интернет для анализа не нужен. Распознавания лиц нет. Подробно — [ARCHITECTURE.md](ARCHITECTURE.md).

## 4. Нормативные источники и сопоставление с видео

Основной источник — Правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей в банках второго уровня (утв. постановлением Правления НБРК от 29.11.2019 № 231), [adilet.zan.kz/rus/docs/V1900019680](https://adilet.zan.kz/rus/docs/V1900019680). Пункты прочитаны в действующей редакции.

Принцип: каждой категории соответствует правило с условиями применимости, исключениями и наблюдаемыми признаками ([app/rules.json](../app/rules.json)). Модель сначала описывает видимое на всей записи, затем каждый кандидат проверяется по условиям своей категории. Нарушение выдаётся только при видимых признаках. Если для вывода нужны невидимые данные (проводка, сверка, регистрация в системе), это указывается в ограничениях, а не утверждается.

## 5. Типы нарушений

| Тип | Что распознаётся | Пункт НБРК № 231 |
| --- | --- | --- |
| Уход во время обслуживания | Кассир покидает рабочее место при продолжающемся обслуживании. | п. 22 |
| Пересчёт без клиента | Возможный пересчёт в рамках клиентской операции без присутствия клиента. | п. 20 (часть первая); п. 31, подп. 4) |
| Пересчёт без контролёра | Возможное отсутствие контролёра при операции, требующей его участия. | п. 42 |
| Деньги предыдущей операции | Возможное оставление денег завершённой операции без необходимых мер защиты. | п. 20 (часть вторая) |
| Смешение денег клиентов | Возможное смешение денег разных клиентских операций. | п. 20 (часть вторая); п. 21 |
| Передача денег сотрудниками | Видимая передача денег между участниками, предположительно сотрудниками. | п. 15 |
| Личные предметы в кассовой зоне | Возможное размещение запрещённых личных предметов или явно личных денег. | п. 12 |

## 6. Ограничения и известные ошибки

- Анализ только визуальный, по одной камере. Правильность проводки, сверки и регистрации операций по видео не проверяется.
- Роли (кассир, клиент, контролёр, инкассатор) определяются по действиям, не по лицам; при перекрытии или выходе из кадра роль может быть определена неверно.
- Выход человека за границу кадра не доказывает его отсутствие на месте.
- Результат — подсказка проверяющему, а не юридическое или дисциплинарное заключение.
- Лимит обработки — 5 минут на видео, включая очередь; при превышении задание получает `failed`.
- Качество модели: ‹точность, пропуски и ложные срабатывания на обучающих роликах — заполнить по замерам тиммейта›.
- Известные случаи ошибок: ‹заполнить по замерам›.
- Публичный адрес Cloudflare quick tunnel меняется при перезапуске туннеля.
