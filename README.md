# Касса — MVP для ForteBank Datathon 26

Локальный помощник проверяющего: загрузка MOV → фоновый анализ → возможные события, таймкоды, исходные кадры и ограничения вывода. FastAPI, React/TypeScript, SQLite, FFmpeg через PyAV, один Qwen3-VL worker. Это прототип; реальный GPU inference проверен на синтетическом ролике, качество и скорость на банковских видео пока не измерены.

Текущий GPU-сервис команды доступен на Mac через SSH-туннель: http://127.0.0.1:8001. [Подключение RunPod и управление сервисом](docs/RUNPOD.md).

## Быстрый запуск на Mac без GPU

Из корня проекта:

```bash
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -e '.[dev]'
.venv/bin/python scripts/init_env.py
cd frontend
npm ci
npm run build
cd ..
.venv/bin/uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

Откройте http://127.0.0.1:8000. Браузер запросит логин `reviewer` и пароль `CASH_UI_PASSWORD` из локального `.env`. Регистрации нет. Это отдельный пароль, не ключ API жюри. `.env` создаётся с правами 0600, существующий файл скрипт не перезаписывает. Не добавляйте секреты в `VITE_*`, браузерные хранилища, Git или команды benchmark.

По умолчанию `CASH_MODEL_ENABLED=false`: UI и защищённые маршруты доступны, readiness отвечает 503, анализ — 503. **Демонстрационных вердиктов нет.** Для реального анализа выполните GPU-подготовку ниже. На Mac без CUDA интеграция Qwen не запускается; MPS-адаптер не реализован.

## GPU и локальные веса

Референс — Linux x86_64 с NVIDIA GPU. На RTX A5000 24 ГБ проверены загрузка модели и короткий синтетический прогон через API; длинные ролики, нагрузку и совместимость Docker-образа нужно проверить. Никакие платные ресурсы автоматически не создаются.

```bash
uv pip install --python .venv/bin/python -e '.[gpu,dev]'
# Зафиксированный snapshot, его tokenizer/config проверены локально.
# Этот шаг скачивает только веса, не читает и не отправляет датасет.
HF_HUB_OFFLINE=0 TRANSFORMERS_OFFLINE=0 .venv/bin/python scripts/download_model.py \
  --revision ebb281ec70b05090aa6165b016eac8ec08e71b17 --destination models/Qwen3-VL-4B-Instruct
```

Установите `CASH_MODEL_ENABLED=true`, `CASH_MODEL_PATH` на локальную директорию и `CASH_DEVICE=cuda:0`. Запустите сервер одной командой uvicorn выше. Проверка готовности: `GET /health/ready` — 200 только после загрузки весов, 503 во время загрузки или при ошибке. `/health/live` проверяет только HTTP-сервер. Веса загружаются один раз на процесс, не на каждый запрос. LoRA подключается опционально через `CASH_LORA_PATH` на локальную директорию; обучение не запускается. Qwen3.5-4B требует отдельного адаптера, простая подмена модели не поддерживается.

Адаптер основан на [официальной карточке Qwen3-VL](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct). Используются `Qwen3VLForConditionalGeneration`, `AutoProcessor`, локальные изображения с явными таймкодами, `sdpa`, bf16 и ограничение генерации. Зависимости GPU зафиксированы на Torch 2.8.0 / torchvision 0.23.0 / Transformers 4.57.1; реальный GPU-прогон этих версий выполнен в отдельном Python 3.12 окружении RunPod. Настоящий процессор проверен на CPU с синтетическими изображениями, включая 169 кадров; модельный inference проверен на трёхсекундном синтетическом MOV, без банковского датасета. Базовые зависимости доступны в `requirements-local.lock` для воспроизведения проверенной локальной среды.

## Контейнер

```bash
# UI/API без модели:
docker compose up --build
# На разрешённом Linux GPU-хосте с NVIDIA Container Toolkit и скачанными весами:
docker compose -f compose.yaml -f compose.gpu.yaml up --build
```

Образ не содержит видео, секретов или весов. Веса монтируются read-only; задания — отдельный volume. Контейнер работает от uid 10001; убедитесь, что модель доступна этому пользователю. Для LoRA путь внутри контейнера задайте явно и смонтируйте его read-only. Compose по умолчанию слушает только loopback. Публичный URL для жюри ещё не развёрнут: нужен HTTPS reverse proxy, ограничение тела до 101 МБ, ограничения времени загрузки и защита секретов. Собственный GPU-хостинг необходимо согласовать с организаторами до отправки датасета. Не считайте старую цену RunPod актуальной: проверяйте цену/наличие перед арендой. Контейнер не проверен сборкой на этом Mac: Docker отсутствует.

## API жюри

Оба маршрута требуют корректный `X-API-Key`. Ключ хранится в `CASH_API_KEY`.

```bash
curl -X POST http://127.0.0.1:8000/api/v1/analyze \
  -H "X-API-Key: $CASH_API_KEY" -F 'file=@/absolute/path/video.mov'
# 202: {"job_id":"..."}
curl http://127.0.0.1:8000/api/v1/jobs/<job_id> -H "X-API-Key: $CASH_API_KEY"
```

`processing` → `done` или `failed`. В done строго сохраняются job_id, status, verdict, violations; у каждого события type, timecode_sec, description, evidence_frames (1–3 JPEG base64). no_violation не входит в violations. Ошибка декодирования/модели/валидации/таймаут никогда не возвращает no_violation. Неизвестный job_id — 404; неверный ключ — 401; неготовая модель — 503; заполненная очередь — 429; превышение размера — 413; неверное расширение — 415. Повторной автоматической отправки отклонённого файла нет.

Расширенный маршрут `/ui/api/jobs/{job_id}` защищён UI-паролем и содержит этап, интервалы, observed_action, rule_id, uncertainty_reason, условия применимости, ограничения, дополнительные наблюдения и метрики. `/ui/api/jobs/{job_id}/video` поддерживает защищённое воспроизведение производной MP4. Исходные файлы и каталог runtime не публикуются. Один пароль предоставляет общий командный доступ; персональных аккаунтов нет.

## Проверки и оценка

Проверки процессора в `tests/test_processor.py` опциональны: требуют публичных tokenizer/config-файлов в `models/processor-smoke`. В текущем локальном окружении они подготовлены без скачивания весов. На чистом checkout эти два теста будут пропущены; остальные тесты не требуют модели или сети. Тестовый хост `tests/preview_server.py` используется только для визуальной QA с пустым временным хранилищем и отключённой моделью, не является точкой запуска сервиса.

```bash
.venv/bin/python -m pytest -q
cd frontend && npm run build
```

Все подставные модели расположены только в `tests/`. Тесты используют синтетические цветные кадры, не исходные банковские видео. Они проверяют договор API, ключи, защиту UI, очередь, сбои, интервалы, доказательства, реальное декодирование/кодирование и импорт разметки; не измеряют качество Qwen.

Аудит исходных данных без чтения кадров:

```bash
.venv/bin/python scripts/audit_dataset.py \
  --videos /Users/azamat/Downloads/open/videos \
  --labels /Users/azamat/Downloads/open/open_labels.xlsx \
  --output reports/dataset-audit.json
```

После запуска настоящей модели, сначала один длинный ролик, затем несколько одновременных запросов. Ключ передайте через окружение. По умолчанию benchmark запрещает сетевой адрес за пределами loopback.

```bash
.venv/bin/python scripts/benchmark.py --videos /path/to/videos --longest 3 \
  --concurrency 1 --output reports/benchmark-long.json
.venv/bin/python scripts/benchmark.py --videos /path/to/videos --longest 3 \
  --concurrency 3 --output reports/benchmark-load.json
.venv/bin/python scripts/evaluate.py --audit reports/dataset-audit.json \
  --benchmark reports/benchmark-long.json --output reports/evaluation.json
```

Benchmark сохраняет полное время запроса, p50/p95, сбои, отказы и превышения 300 секунд. Расширенный результат в SQLite/UI содержит время этапов, очередь, пиковую выделенную/зарезервированную VRAM и RSS процесса. Failures не включаются в no_violation и отдельно отражены в метриках. Разметка категорий и интервалов ещё нужна для оценки событий; релевантность кадров требует независимой ручной проверки. Формат и валидатор: [docs/ANNOTATIONS.md](docs/ANNOTATIONS.md).

## Нормативная база и ограничения

Все категории в `app/rules.json` имеют `source_verification_status=unverified`, `normative_source=null`. [Постановление НБРК №231](https://adilet.zan.kz/rus/docs/V1900019680) — отправная точка, а не подтверждённое обоснование категорий. При исследовании 17 октября 2026 текст через доступный веб-инструмент не загрузился (страница потребовала JavaScript). Пункты не выдуманы. До сдачи команда должна проверить актуальный текст и применимость источников.

Видимая передача не доказывает отсутствие регистрации; отсутствие человека в кадре не доказывает отсутствие в помещении; наличие денег не доказывает нарушение. Роли определяются только по контексту действий. Лица не идентифицируются. Категории, для которых условия применимости не установлены, должны оставаться дополнительными наблюдениями. JSON-валидация не гарантирует истинность ответа модели.

Редкая выборка и ограниченное разрешение могут пропустить короткое действие или мелкие предметы. Финальный ракурс и новые категории требуют отдельной оценки. Нельзя обещать чувствительность, точность или лимит 5 минут до GPU-замеров. Текущий watchdog ограничивает работу, но не делает таймаут успешным результатом. [Архитектура и технические ограничения](docs/ARCHITECTURE.md).

Исходные данные не меняются. Производные и отчёты хранятся в игнорируемых runtime/reports того хоста, на котором выполняется сервис. На RunPod создан только синтетический тестовый материал. Автоматический срок хранения пока не реализован: после окончания разрешённого использования удалите данные заданий, отчёты с описаниями и резервные копии согласно условиям организаторов. Не публикуйте материалы датасета. Обучение не запускалось; для подключения использован уже арендованный командой Pod, новые платные ресурсы не создавались.

## Повторная визуальная проверка

Версия `visual-discovery-v2` исправляет пропуск уточнения после пустого первого обзора: отрицательный обзор обязательно перепроверяется по всей записи. Поиск видимых кандидатов отделён от проверки применимости категории; детализация получает больше разрешения. В интерфейсе видны количество входных кадров, описание сцены по версии модели и примеры входной выборки. Сервис анализирует выборку изображений, а не все кадры исходного видео. Предыдущие результаты сохраняются; для нового анализа нужна повторная загрузка. Глубокая ссылка на защищённый результат: `/?job=<job_id>`. Изменение не является подтверждением качества классификации.
